# Media Dock 3.0.4 本地维护候选

本轮针对启动失败、B 站试看内容被误当作完整成品，以及 Cookie 替换后未开始的任务仍引用旧认证配置的问题。发布前仍需走现有的平台打包验收流程。

本地构建版本：`3.0.4-preview.4`，仅 macOS。

## 2026-10-26 macOS 专用版本

- 按维护者要求移除 Windows 运行路径、编码、进程终止、文件路径兼容与文件名限制，统一使用 macOS 的路径、权限、UTF-8 和进程组。下载资产只选择对应 macOS 架构。
- 删除 Windows CI、原生构建与验证器、PowerShell 辅助脚本、Windows 图标及生成脚本，移除 Windows 签名配置和不再使用的 `cross-env` 直接依赖。默认打包命令现在进入 macOS 构建流程。
- 保留 macOS Apple Silicon 与 Intel，更新平台元数据、说明、现行发布流程与测试夹具。旧版发布记录和架构决定保留为历史证据，现行平台范围见 ADR 0038。
- 本候选包含此前的启动恢复、Cookie 隔离及 B 站登录核验、设置刷新与安全重启；用户媒体、任务数据、真实登录资料和本机临时目录不进入提交。

macOS 专用版本验证：完整回归 **189 项全部通过，0 失败、0 跳过**；构建、静态检查、脚本语法与差异检查通过。范围包括真实本机进程重启、下载进程组清理、Cookie 副本隔离、文件权限、中文与空格路径、导出命名及设置页流程。第一方运行代码、脚本、测试和 CI 中的 Windows 专属分支检查为零。尚未制作或发布新的安装包。

## 2026-10-26 设置刷新与应用重启

- 03 在打开应用时读取已安装的 yt-dlp / Deno 版本；新增“刷新状态”，只读取本机版本，不联网检查或下载安装。原“检查更新”继续负责查询新版本。
- 内核更新成功后立即刷新版本。若一个工具已安装、另一个工具下载失败，也重新读取实际安装结果并保留“重启后生效”提示；手动刷新和重新检查都不会把待重启状态误清除。
- 04 新增“刷新状态”，重新读取认证配置并显示反馈；导入 Cookie 后仍立即生效，不重载页面，也不清空工作台的来源和保存位置。刷新本地配置不宣称网站已验证登录有效。
- 03 新增“重启应用”。确认框默认取消，并说明未提交的链接、选择和编辑不会保留；任务记录和登录资料保留。
- 主进程在确认前后分别检查任务、来源检查及维护活动，防止另一个窗口在确认期间开始工作。等待中、处理中、检查、导入或更新期间不执行重启；重复点击也只安排一次重启。
- 重启复用既有退出清理，等待任务引擎和数据库关闭后由 Electron 重新启动，沿用原启动参数和数据目录。设置页也补充了操作失败的可见提示。

验证结果：构建、静态检查和差异检查通过；完整回归共 200 项，199 项通过、0 失败，1 项 Windows 专属检查跳过。界面测试覆盖刷新失败后重试、不重载页面更新状态、重启取消及重试、重复点击、任务进行中禁用重启、内核部分安装失败后保留待重启提示。macOS 原生重启测试在临时数据目录加载实际主进程和预加载桥，验证了取消、原进程清理数据库与 IPC、第二个进程重新打开同一数据目录及保留已保存状态。设置页截图已检查，截图使用模拟版本和空认证配置。

现有日常应用进程需要退出并通过原启动器重新打开一次才能载入这次代码修改；本轮没有自动关闭日常应用或替换用户 Cookie，也未提交、推送或发布。打包应用的重启仍需对应环境验收。

## 2026-10-11 Cookie 隔离与登录判断

- 来源识别、画质检查、每次下载及兼容重试均创建独立的私有 Cookie 副本。yt-dlp 不再接收导入原件的路径；各个进程的回写相互隔离，完成、失败、超时或取消后清理副本。
- 取消时先等待运行进程退出；对忽略终止信号的子进程有有界的强制退出处理。关闭应用会等待下载和来源检查的清理完成。
- 对使用 B 站认证配置的网络操作，先核对适用于官方登录接口的 Cookie 域名、路径、凭据和期限，再通过 B 站官方登录接口确认是否已登录。仅把该接口所需作用域的 Cookie 发送给 B 站，禁止跟随重定向。
- 网站确认未登录与网络中断、请求受限、响应异常使用不同的问题编号。网络问题提供重新检测入口，不要求用户误换 Cookie；普通账号没有大会员不等同于登录失效。
- 顶部状态改为“已导入登录信息”，避免把文件导入成功表述为网站已确认登录有效。MediaCookies 扩展继续只做本地导出检查，真实登录确认由 Media Dock 执行。

本轮完整测试为 189 项：188 通过、0 失败，1 项 Windows 专属检查跳过。另用真实 B 站做了两次并发只读来源检查：均返回完整时长，副本路径不同，原始文件的字节和修改时间均未变化，副本均已清理。测试没有下载视频，也未记录 Cookie 值。

本机已通过原启动入口打开 `3.0.4-preview.2` 主窗口，并显示新的“已导入登录信息”状态。MediaCookies 0.2.2 经 Chrome 测试页面生成的模拟交接包也已通过 Media Dock 导入模块验收；该测试使用隔离数据目录，不替换用户登录资料。

## 行为变更

- macOS 源码启动器恢复缺失的锁定依赖，并修复不完整的 Electron 运行组件；不会改写依赖锁文件或用户媒体。只读启动检查仍不联网、不修复。
- 来源检查和画质预览保留下载工具的警告。明确的 Cookie 失效、仅能试看、会员/充电/课程权限不足会提示更新登录资料并确认完整观看权限；普通 HTTP 403 不被误判为 Cookie 过期。
- 下载命令禁止跳过不可用分片。下载工具即使返回成功，只要存在明确的试看或登录失效警告，也不会交付该文件，而是清理本任务的暂存区并进入“需要处理”。
- 导入 MediaCookies 后立即刷新画质和未开始的任务计划，保留已选画质上限、来源和保存位置；从认证问题入口返回时可以在同一进程中重新处理，无需重启，也不会自动开始下载。
- 更新请求在 30 秒内未完成时退出并说明超时；运行组件下载连续 60 秒没有数据时中止，清除临时文件并保留旧文件。正常持续传输不受总时长限制。
- 下载内核的“需要重启”提示保留到应用真正重启；重新检查期间禁用安装按钮。此规则适用于内核更新，Cookie 替换立即生效。
- 文件和目录选择器出错时显示可恢复提示，再次选择或取消即可继续。

2026-10-03 验证结果：完整测试共 172 项，171 项通过、0 项失败、1 项仅适用于 Windows PowerShell 的检查跳过；构建、静态检查与差异检查通过。原始外层 macOS 启动入口已实际打开主窗口，任务中心正确显示本次真实下载的完成记录。正片为 1920×1080，视频与音频时长约 1166.44 秒，整段音画解码无错误；试看提示与 Cookie 导入成功提示已检查实际截图。

## 验收边界

试看拦截以下载工具明确返回的访问限制为依据；它不能赋予账号原本没有的观看权限，也不能保证所有网站都准确报告限制。本轮不修改平台签名、不自动升级系统级工具、不发布 GitHub Release。当前仅维护 macOS；旧版多平台测试数量保留为历史记录。
